# Технический аудит OLGA Dental Clinic

Исходный commit: `b52dc6849d94baac48c32aa0d35f4e62126f74a2`, ветка `preview/soni-development`. Изменения готовятся в `audit/olga-quality-2026`. Исходная фиксация — [BASELINE.md](BASELINE.md). Версии и зависимости после исправлений — [SECURITY.md](SECURITY.md).

## Архитектура и реализованные функции

Подтверждено по всему исходному дереву приложения:

- App Router: 20 страниц контента — главная, услуги, акции, врачи, о клинике, контакты, два юридических проекта и 12 страниц услуг с `generateStaticParams`. Дополнительно экспортируются 404, robots, sitemap и icon. Профили семи врачей открываются в модальном окне; отдельных URL врачей нет.
- Единые `BookingProvider` и `GlobalBookingModal` сохраняют контекст врача/услуги. У формы нет свободного поля для диагноза/сообщения. Пример PHP, приватная конфигурация, схема MySQL и административный интерфейс находятся только в `deployment/beget`, вне `public`.
- Контент услуг и статьи разделены на типизированный каталог и два тематических файла. Все 12 услуг имеют статью и изображение, все семь врачей — фотографию. Исходная автоматическая проверка прошла; медицинские тексты, цены и сведения о врачах в ходе аудита не редактировались.
- Светлая/тёмная тема реализована через `next-themes`, анимации — через Framer Motion и CSS. Карточки врачей имеют фильтры, главная — карусель. Отзывы представлены локальными данными и ссылкой на источник.
- Метрика требует отдельного согласия и ограничена production-доменом; preview-форма демонстрирует валидацию без передачи данных. Публикация реальной записи требует отдельных build-флагов и разрешающей серверной конфигурации.
- `output: "export"`, `trailingSlash: true`, `images.unoptimized: true` соответствуют обычному статическому Apache-хостингу. PHP публикуется отдельно. Vercel-конфигурация добавляет `X-Robots-Tag: noindex, nofollow, noarchive` ко всем preview-ответам.

Server Components используются для страниц статей и route metadata; интерактивные секции остаются Client Components. Домашняя страница получила небольшой серверный wrapper для canonical; существующий интерактивный код перенесён без изменения содержания в `components/pages/home-page.tsx`. У клиентской страницы акций metadata задаётся серверным layout.

## Сложность, дублирование и сопровождение

Экспертная оценка: наиболее сложные компоненты — Navbar, Services, DoctorsPage и AboutPage, преимущественно из-за большого количества локальных Tailwind-классов и декоративных слоёв. Риск сопровождения выше у ручной геометрии карусели, нескольких систем scroll/focus lock и client/server guards. Общий hook устраняет дублирование управления модальными окнами; масштабное разбиение компонентов ради архитектуры не выполнялось.

`components/sections/about.tsx` не импортируется, в отличие от используемого `components/pages/about-page.tsx`. Это возможный предыдущий вариант секции; он сохранён. `lib/motion.ts` имеет неиспользуемые экспорты `transition` и `viewport`; общий `reveal` используется. Шаблонные `public/{next,vercel,globe,file,window}.svg` не используются в приложении. Пакет `resend` не импортируется действующим кодом. Эти находки не означают удаления работающей функции; очистка не является блокером текущего аудита.

Команда `npm start` оставлена как `next start`, хотя для `output: "export"` следует обслуживать `out/` статическим HTTP-сервером. Это ограничение локального workflow (P3), не ошибка экспортируемых страниц. Не применять её как команду Beget-развёртывания. README исходной ветки краток; подробная процедура PHP/Apache есть в `deployment/beget/README.md`.

Каталог услуг, статьи и карточки акций содержат отдельные ценовые строки. Автоматическая сверка слугов/изображений есть, но клиническую и ценовую актуальность должен подтверждать представитель клиники. Значения в ходе аудита не исправлялись по предположению.

Итоговый адресный браузерный тест ScrollToTop прошёл **8 из 8** assertions: три независимых возврата Back восстанавливают `y=1200`, три перехода из акций и прямой fragment URL показывают целевую карточку в viewport; прокрутка серверного HTML до загрузки задержанного на 1800 мс JavaScript сохраняется после hydration (`1200 → 1200`). Доказательство: [scroll-final.json](evidence/scroll-final.json), воспроизводимый [скрипт](tools/scroll-regression.mjs).

В промежуточной версии initial hydration ещё сбрасывал прокрутку: [slow-JS до последнего исправления](evidence/scroll-slow-js-before.json) и [промежуточный прогон](evidence/scroll-interim.json). Эти результаты сохранены для прослеживаемости и не считаются финальным PASS. Итоговый guard выполняет ручную прокрутку только при реальной смене pathname; fragment/history обрабатывает Next.js. Остальные окончательные браузерные сценарии приведены в [REGRESSION.md](REGRESSION.md).

Контракт production API изменён только в подготовленных файлах. Административная система не включена в статический экспорт. Настройки и реальные файлы Beget, рабочая БД, права production-файлов, WAF и секреты недоступны и не считаются проверенными. Browser mock не доказывает исправность production API; локальные PHP/MySQL-тесты и вопросы запуска описаны отдельно в [SECURITY.md](SECURITY.md).

Результат не является гарантией соответствия медицинского содержания или законодательства. Юридические проекты остаются неутверждёнными.
